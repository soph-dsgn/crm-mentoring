# Архитектура «Кураторской»

React обращается к FastAPI с одного HTTPS origin. PostgreSQL хранит рабочие данные, права, статусы, историю и базу знаний. SQLite используется в локальной разработке и изолированных проверках. При смене окружения приложение загружает доступные записи с сервера.

У профиля одна текущая группа. Перенос меняет внешнюю связь без замены профиля. Секции и задачи поддерживают оптимистические версии и уникальные позиции. Снимки домашнего задания продолжают ссылаться на ту же задачу после перемещения.

Локальные AppData и KnowledgeData доступны как отдельные источники миграции. Пользователь выбирает и проверяет файл до подтверждения. Webroot включает клиентский код и публичные визуальные ресурсы.

## Архитектурный стиль

Выбран модульный монолит. Для команды и объёма 50–300 учеников он даёт транзакции между стратегиями и ДЗ без распределённой инфраструктуры, простой деплой и ясные границы для роста.

```text
HTTP / FastAPI
    ↓
API-схемы и зависимости доступа
    ↓
сервисы вариантов использования и объектные проверки прав
    ↓
репозитории / SQLAlchemy Unit of Work
    ↓
SQLite → PostgreSQL
```

Модули: `auth`, `users`, `groups`, `students`, `strategies`, `meetings`, `homeworks`, `knowledge` и `legacy_io`. Общие `core` и `db` содержат только инфраструктуру. Модуль не должен изменять таблицы другого модуля напрямую: межмодульный сценарий координирует сервис приложения в одной транзакции.

## Текущая структура

```text
backend/
  app/
    api/              # композиция HTTP-маршрутов и /health
    core/             # настройки окружения
    db/               # metadata, engine, session
    modules/          # предметные модели, схемы и сервисы
  migrations/         # Alembic revisions
  tests/              # изолированные backend-тесты
  pyproject.toml
docs/
  architecture/
```

Foundation использует синхронный SQLAlchemy. Для текущей нагрузки это проще и достаточно; FastAPI запускает обычные `def`-обработчики в thread pool. Имена ограничений заданы явно, URL БД приходит из окружения, SQLite-специфичный `check_same_thread` изолирован в фабрике engine, а Alembic включает batch-режим только для SQLite. PostgreSQL 18 поддерживается через Psycopg 3 с консервативным pool; dialect-aware migrations сохраняют одинаковые межтабличные и append-only инварианты.
