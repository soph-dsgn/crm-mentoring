# Приёмка «Кураторской» на Windows

Используйте Docker Desktop в режиме Linux-контейнеров и PowerShell из корня проекта. Скрипт создаёт отдельный проект Docker Compose `kuratorskaya-manual` и постоянный том с синтетической базой PostgreSQL 18.4. Порт публикуется только на loopback.

```powershell
.\deploy\start-acceptance.ps1
docker compose -f deploy/compose.acceptance.yml run --rm backend python -m app.cli.bootstrap_owner --login acceptance.owner --confirm-database acceptance --confirm-first-owner
```

Откройте `https://localhost:8443`. Разрешите локальный самоподписанный сертификат только для этого адреса. Проверки живости и доступности базы находятся на `/health/live` и `/health/ready`.

Bootstrap запускается один раз в пустой базе. Войдите с одноразовым паролем из интерактивного терминала и задайте новый. После сохранения сразу откроется рабочее место. Из раздела «Аккаунты» создайте двух тестовых кураторов и сохраните показанные пароли в защищённом хранилище. Откройте отдельные профили браузера и смените оба временных пароля.

## Ручные сценарии

- [ ] На чистой установке открывается серверный обзор. Проверьте вход, выход, принудительную и добровольную смену пароля и перезагрузку. Новый пароль — от 8 символов, с цифрой и спецсимволом. После смены временного пароля рабочее место открывается сразу, без повторного ввода временного пароля и без повторного входа; другие устройства пользователя выходят из аккаунта
- [ ] Создайте ученицу вручную, откройте «Стратегия» → «Импортировать из Notion» и выберите PDF-экспорт стратегии. Сверьте разделы, задачи, статусы и выбранные поля профиля в превью, затем импортируйте. Отмена не записывает данные. Повторный импорт в непустую стратегию отклоняется. Поправьте задачи и профиль вручную
- [ ] Два куратора независимо создают группы и тестовые профили. Проверьте редактирование, плановую и фактическую даты, фильтры, поиск, архив и восстановление
- [ ] Куратор переводит ученицу между своими активными группами. Владелец переводит её между группами разных кураторов. Проверьте прежние ID, профиль, стратегию, встречи, задания и назначенный аккаунт
- [ ] Создайте стратегию, два раздела и задачи. Проверьте переименование и порядок, перенос задачи, запрет удаления непустого раздела, удаление пустого, архив и восстановление задачи
- [ ] Запишите срок, блокер и ссылки. Отправьте исходную задачу Ане, верните на доработку и согласуйте. Проследите, что статус выполнения меняется отдельно
- [ ] Создайте встречу, отредактируйте и восстановите из архива. Выберите задачи и сформируйте ДЗ. Сохраните черновик, скопируйте текст и отдельно выдайте ДЗ
- [ ] Зафиксируйте сдачу как куратор. Верните работу с комментарием, зафиксируйте повторную сдачу и примите. Сверьте прогресс, снимки задач и историю. Попытка вручную изменить статус задачи во время проверки должна отклоняться
- [ ] Одновременно откройте запись в двух окнах, сохраните разные изменения. Проверьте сообщение о конфликте и возможность скопировать несохранённый ввод перед повторным редактированием
- [ ] Владелец назначает и переназначает группы, сбрасывает пароль и отключает куратора после передачи групп. Проверьте ревокацию сессий и передачу прав владельца
- [ ] Активируйте пустую базу знаний или импортируйте пробную KnowledgeData v1. Проверьте поиск, добавление, правки, избранное, архив, восстановление и экспорт владельца. Проверьте импорт DOCX, HTML и Markdown
- [ ] Для AppData подготовьте синтетическую копию и отдельную базу без рабочих записей. Аккаунты кураторов можно создать заранее. Сначала проверьте ошибочные связи и дубликаты без записи. Затем проверьте назначения, подтвердите импорт и повторите на том же файле для проверки идемпотентности
- [ ] Проверьте desktop и мобильную ширину, работу с клавиатуры и фокус диалогов. Проверьте состояние без записей, потерю сети, ошибки и повтор запросов
- [ ] Проверьте существующий кабинет ученицы на синтетическом аккаунте. Попытки изменить чужие записи и отправить мутацию без CSRF должны отклоняться

## Автоматическая браузерная проверка

На отдельной чистой базе запустите окружение по первой команде. Playwright сам инициализирует тестового владельца. Для браузерной проверки используется отдельная синтетическая база. Backend CI проверяет PostgreSQL 18.4 и фактическое отсутствие пропусков.

```powershell
cd frontend
npm ci
$env:CRM_ACCEPTANCE_BROWSER = 'msedge'
npm run verify:release
```

Для Chromium Playwright можно выполнить `npx playwright install chromium` и запускать тест без переменной. Для повторного чистого прогона остановите текущий Compose-проект и задайте новое имя через `$env:COMPOSE_PROJECT_NAME` перед запуском скрипта. Продолжайте использовать это имя в командах запуска, тестов и остановки. Порт 8443 одновременно может занимать только одно окружение.

## Остановка и сохранение данных

```powershell
docker compose -f deploy/compose.acceptance.yml down
```

Том при этом остаётся. Команды не используют локальную SQLite, пользовательские хранилища браузера или производственный PostgreSQL. Скачивайте старые браузерные копии из прежнего браузерного профиля и храните их отдельно. Для передачи оператору сверяйте результаты приёмки с [порядком развёртывания](../deployment/README.md).
